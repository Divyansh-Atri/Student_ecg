# Comprehensive Technical Overview: VitalModel

This document is a deep-dive reference guide designed for Large Language Models (LLMs) and developers to gain an intrinsic understanding of the **VitalModel** codebase. It covers the exact algorithms, module interactions, data schemas, API routes, and the fully remediated security posture.

---

## Quick Start (Start Everything)

To seamlessly start all components of the VitalModel system (including the MedGemma-Agent host, the UI, and the ECG Preprocessing Pipeline), use the provided unified startup script:

```bash
./start_vitalmodel.sh
```

**What this script does:**
1. Starts the **MedGemma-Agent** in the background (API on port 8000, UI accessible at `http://localhost:8000/ui`).
2. Runs the **ECG Preprocessing Pipeline** to process daily ECG batches and update machine learning manifests.

To stop the MedGemma-Agent host later, run:
```bash
./MedGemma-Agent/stop.sh
```

To view live server logs:
```bash
tail -f MedGemma-Agent/server.log
```

## 1. System Architecture & Data Flow

VitalModel is a secure, end-to-end clinical decision support (CDS) system divided into two primary sub-systems:
1.  **ECG Preprocessing & Quality Analysis (Edge/Data Tier):** Ingests raw, noisy sensor data, applies advanced Digital Signal Processing (DSP), and uses Machine Learning to extract clinical metrics (Signal Quality, Arrhythmia Burden).
2.  **MedGemma Agent (Clinical Reasoning Tier):** A FastAPI-based secure service that accepts the extracted metrics, applies deterministic clinical rules (NEWS2, qSOFA), retrieves historical patient context via RAG, and queries a local LLM (MedGemma via Ollama) for a synthesized clinical summary.

### Data Flow Example (ECG to LLM)
1.  `raw_ecg.csv` ingested by `ecg-preprocessing-and-quality-analysis/scripts/clean_ecg.py`.
2.  Signal is cleaned using DSP (Hampel, Butterworth filters).
3.  Extracted metrics are formatted into JSON via `tools/medgemma_bridge.py`.
4.  JSON sent to `MedGemma-Agent` at `POST /api/v1/ecg/analyze`.
5.  API validates `X-API-Key`.
6.  `ecg/prompts.py` builds the LLM prompt.
7.  MedGemma generates a clinical summary (JSON schema).
8.  Data is encrypted (AES-256) and stored in SQLite.

## 2. Component Deep Dive: ECG Preprocessing Pipeline

Located in `ecg-preprocessing-and-quality-analysis/`.

### 2.1 Signal Processing Pipeline (`scripts/clean_ecg.py`)
This script contains the core DSP logic to prepare noisy ECG data for downstream ML.
*   **Timestamp Sanitization:** Deduplicates and enforces uniform grid resampling.
*   **Outlier Suppression (Robust Clipping & Hampel Filter):** Removes ADC glitches and extreme motion artifacts using a sliding median window (~200ms) to preserve sharp QRS morphology.
*   **Zero-Phase Filtering (`scipy.signal.filtfilt`):**
    *   *High-pass (0.5 Hz):* Removes baseline wander (respiration, electrode drift).
    *   *Notch (50 Hz):* Suppresses powerline interference.
    *   *Low-pass (40 Hz):* Removes high-frequency EMG noise.
*   **NeuroKit2 Refinement:** Optional secondary pass using `nk.ecg_clean`.
*   **R-Peak Detection:** Uses a multi-tiered approach (NeuroKit2 -> SciPy Pan-Tompkins variant -> adaptive prominence fallback) to detect R-peaks and calculate Heart Rate (HR) and RR Intervals.

### 2.2 Quality Scoring & ML 
*   **Quality Metrics:** Calculates Frequency-domain SNR (in-band 0.5-40 Hz vs out-of-band >40 Hz) and baseline drift ratios. Segments are scored from "EXCELLENT" to "UNUSABLE".
*   **Arrhythmia Detection:** `ml/predict_arrhythmia.py` processes the normalized signal to calculate `probability_arrhythmia` and `arrhythmia_burden` percentages.

## 3. Component Deep Dive: MedGemma Agent

Located in `MedGemma-Agent/`. A FastAPI service bridging rules, ML, and LLMs.

### 3.1 API Routes (`api/routes/`)
*   **`ecg.py`:** `POST /ecg/analyze` - Accepts ECG metrics, queries LLM, returns clinical summary.
*   **`vitals.py`:** Handles real-time vitals. Routes vitals through the Guardrails engine before LLM processing.
*   **`alerts.py`:** Manages clinical alerts generated by the system.
*   **`ehr.py`:** Ingestion endpoints for Patient Electronic Health Records.
*   **`abg.py`:** Arterial Blood Gas interpretation endpoints.
*   **`audit.py`:** Access to the secure, hash-chained audit log.

### 3.2 Guardrails & Clinical Rules (`guardrails/clinical_rules.py`)
Provides deterministic clinical safety nets independent of the LLM.
*   **NEWS2 (National Early Warning Score):** Calculates scores (0-3) for Systolic BP, Diastolic BP, Heart Rate, and SpO2. Total scores $\ge$ 7 trigger `CRITICAL`.
*   **qSOFA (Quick SOFA):** Checks SBP $\le$ 100, HR $>$ 100 (custom threshold), SpO2 $<$ 92%. Triggers `CRITICAL` for high risk.
*   *Design Philosophy:* If Ollama/MedGemma crashes (`LLM_FALLBACK_ON_TIMEOUT=True`), the system relies entirely on these deterministic scores to dictate the `RecommendedAction`.

### 3.3 Retrieval-Augmented Generation (RAG) Pipeline (`rag/`)
*   **Vector Store:** Uses **ChromaDB** to store embedded EHR data.
*   **Embedding Model:** `all-MiniLM-L6-v2`.
*   **Retriever (`rag/retriever.py`):** Uses a fixed, clinically-motivated query ("patient surgical history cardiovascular risk factors prior sepsis infection current medications allergies...") to extract the Top-K most relevant chunks from the patient's EHR to append to the LLM prompt.

## 4. Security Posture & Compliance

The codebase recently underwent a rigorous security audit. All critical vulnerabilities have been **patched**. When modifying this codebase, you must adhere to these established security constraints:

### 4.1 Strict Authentication (No Backdoors)
*   **Middleware (`api/middleware/auth.py`):** All endpoints (except `/docs` and `/health`) are secured via the `X-API-Key` header.
*   *Fix Applied:* A previous `DEV_MODE=True` authentication bypass was completely removed. Do not re-introduce development backdoors.

### 4.2 LLM Prompt Injection Prevention
*   **ECG Analysis (`ecg/schemas.py`, `ecg/prompts.py`):** The LLM prompt is constructed *strictly* from strongly-typed Pydantic floats, ints, and enums (e.g., `burden_pct`, `quality_score`).
*   *Fix Applied:* A vulnerable `prompt_override` string field, which previously allowed users to inject arbitrary text directly into the LLM context, was completely removed.

### 4.3 HIPAA / PHI Compliance (`compliance/phi_handler.py`)
*   **De-identification:** The `phi_handler.deidentify()` function is called *before* any text is stored in ChromaDB or sent to the LLM.
*   *Fix Applied:* The regex for Names was strengthened to catch standalone names (two adjacent capitalized words) rather than only names prefixed by titles.
*   **Encryption:** Data stored in the SQLite database is encrypted at rest using AES-256 via the `cryptography.fernet` library.

### 4.4 Hardened Infrastructure
*   **CORS:** Cross-Origin Resource Sharing is strictly limited to local development URLs (`http://localhost`, `127.0.0.1`).
*   **Command Execution:** Automation scripts (e.g., `tools/automate_all.py`) explicitly use `subprocess.run(..., shell=False)` with a structured list of arguments to prevent Shell/Command Injection attacks via crafted filenames.

## 5. Development Guidelines for LLMs

When generating code or proposing changes for this repository:
1.  **Do NOT** use `shell=True` in subprocess calls.
2.  **Do NOT** bypass the `require_any`, `require_clinician_or_above`, or `require_admin` FastAPI dependencies.
3.  **DO** pass any new string-based clinical text through `compliance/phi_handler.py` before logging or LLM inference.
4.  **DO** ensure that any new LLM prompts are populated by strictly typed Pydantic models to prevent Prompt Injection.
